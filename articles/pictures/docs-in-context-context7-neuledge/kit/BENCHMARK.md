# Бенчмарк docs-in-context: полные результаты

Замер от 2026-06-08. 8 способов доставки документации в контекст AI-агента, измерены одним токенайзером.

## Методология (коротко)

- **Гибридный раннер (TypeScript):** каждый кандидат драйвится своим родным протоколом — MCP-серверы через официальный MCP SDK, CLI через subprocess, локальная библиотека in-process, llms.txt через сырой fetch. Ловится **ровно тот payload, что попал бы в контекст агента** (для MCP это не равно сырому ответу бэкенда).
- **Единый счётчик — `tiktoken o200k_base` для всех.** Относительное сравнение «кто экономнее» при одной линейке точное; абсолют к Claude может гулять ±10–15% (нативной Anthropic-калибровки не было — нет доступа к их счётчику).
- **Две компоненты стоимости токенов:**
  - **STATIC** — разовая прописка инструмента в системный промт (тул-схемы MCP или текст skill-файла). Платится раз за сессию.
  - **PER-LOOKUP** — собственно ответ на каждый запрос.
- **16 запросов, версии из реального lockfile:** Next 16.2.5, React 19.2.6, Zod 4.1.12, Supabase JS 2.81.1, TanStack Query 5.90.21, Tailwind 3.4.18. Смесь: узкие сигнатуры (`revalidatePath`, опции `createClient`, флаги `shadcn`), быстро меняющиеся (React 19 `use`, TanStack v5), bleeding-edge (Next 16 `use cache`, React Compiler, Zod 4 `z.email()`), широкие «как сделать X» (тест на раздувание), и ловушка на галлюцинации — несуществующая `quantumfizz-router`.
- **Метрики на каждый lookup:** токены запроса/ответа, латентность p50/p95, число протокольных раундов, retrieval-hit (содержит ли ответ верный актуальный факт — авто-проверка по строке + ручное судейство сырых payload'ов).

## Два разоблачённых near-miss (важно для интерпретации)

**ctx7-CLI: 79% → 93%.** Первый прогон дал CLI 79% против 93% у MCP. Причина — асимметричный вызов: правильная сигнатура `ctx7 library <имя> <запрос>`, а весь вопрос передавался как имя библиотеки (на «use cache» уходил в чужую `next-shared-cache`). После фикса — 93%, ровно как MCP, при меньших токенах. Гипотеза «CLI экономнее MCP при равной точности» подтверждена.

**@neuledge: 57% → 100%.** Первый прогон дал 57% с пустыми ответами на Supabase / TanStack / shadcn. Три бага в обвязке, не в инструменте: (1) пропущен `context add` — neuledge собирает доки из любого источника, доки часто в отдельном репо (`reactjs/react.dev`, не `facebook/react`); (2) scoped-имя `@tanstack/react-query` выпадало из regex-разбора списка; (3) экстрактор ключевого слова брал `string` из `z.string().email()` вместо `email`. После фиксов — 100% при 5 мс.

## Выводы по приоритетам (токены → скорость/актуальность → удобство)

- **Ref** — чемпион по токенам: 170 STATIC + 525 медиана + 100%. Механика `search` → `read_url`. Минус: платный, латентность средняя.
- **@neuledge** при правильном использовании — лучший локальный L1: 100%, 5 мс, offline, без лимитов, запрос 14 токенов. Плата за локальность: ответ дороже Ref (~1880, отдаёт цельные чанки) + разовый `context add` для не-реестровых либ.
- **Context7** силён в обоих режимах (93%): CLI легче по токенам, MCP — zero-config.
- **GitMCP** — хороший fallback по произвольным GitHub-репо (но разброс токенов и нестабильная латентность).
- **Наивный llms.txt** — не как постоянный слой (×5–10 токенов, пик 14 546, 50% попаданий).
- **Никто не сгаллюцинировал** несуществующую `quantumfizz-router` — сигнал доверия.
- **Docfork и Deepcon** — нетестируемы (сломаны сайты вендоров), исключены по объективной причине; вендорский «90% против 65%» остался непроверенным.
