Зачем эта шпаргалка

За последние три месяца Anthropic выкатили столько новинок, что в их собственной документации запутаться легче, чем разобраться. Subagents, Skills, Claude Cowork, Opus 4.7 с миллионом токенов и режимом /fast, экосистема MCP-серверов — каждая фича решает свою задачу, и применить их «все сразу» — гарантированный способ съесть бюджет токенов и не получить пользы.

Эта одностраничная карта отвечает на самый частый вопрос: «вот моя задача — какой из инструментов Claude её решает лучше всего?»

Карта построена так, чтобы можно было распечатать и держать рядом с рабочим столом. Дальше — пять карточек по каждому инструменту: что брать, что не брать, типичные ошибки. И отдельно — комбо-приёмы, которые реально работают, плюс антипаттерны, которые не работают никогда.

Параллельные subagents

Карточка 1 · Параллельные subagents

Top-1 за квартал

Запуск нескольких специализированных Claude-агентов одной командой. Каждый получает свой контекст, свой subagent_type, свой набор инструментов. Можно ставить в фон через run_in_background: true.

Когда брать

  • Сбор информации по большому коду (Explore-агенты)
  • Параллельный аудит — security, dependencies, dead code
  • Подготовка релиза — несколько независимых проверок
  • Сравнительное исследование альтернатив
  • Длинные задачи, где основной чат не должен ждать

Когда НЕ брать

  • Задача не декомпозируется на независимые куски
  • Результаты придётся мерджить — лучше последовательно
  • Простая правка одного файла — overhead больше пользы

Типичные ошибки

  • Запустить 5 агентов на сложную задачу с пересекающимися областями — половина дублируется
  • Забыть передать каждому агенту нужный контекст — отчёты приходят полупустые
  • Использовать для задач, где ценны промежуточные шаги — теряется наблюдаемость

Skills

Карточка 2 · Skills

Модульный CLAUDE.md

Маленькие модульные SKILL.md-файлы с инструкциями для конкретной процедуры. Claude Code находит и подгружает их по триггеру. Альтернатива большому монолитному CLAUDE.md.

Когда брать

  • Задача повторяема по смыслу, но не по конкретным шагам (статья, релиз-чек-лист)
  • Процедуры, которые иначе занимали бы место в CLAUDE.md без постоянной нужды
  • Действия, которые сложно описать алгоритмически, но легко — пошагово
  • Когда хочется делиться рецептами с командой

Когда НЕ брать

  • Задача решается простым скриптом — пиши скрипт
  • Одноразовая операция — оверкилл
  • Когда нужно строгое детерминированное поведение — skill не гарантирует

Типичные ошибки

  • Запихнуть в один skill пять разных задач — он перестаёт срабатывать правильно
  • Не указать триггер в описании — Claude не подгрузит вовремя
  • Делать skill про «какая у тебя профессия» вместо «как её выполнять» — это работа для agent
Памятка про разграничение
Agent= какая у тебя профессия (writer, backend-dev, security-auditor) Skill= как эту профессию выполнять (структурировать статью, накатить миграцию)

Claude Cowork

Карточка 3 · Claude Cowork

GA с 9 апреля 2026

Desktop-агент Anthropic для macOS и Windows. Работает с файловой системой и подключёнными сервисами (Google Drive, Gmail, Slack, DocuSign, QuickBooks, Stripe и др.). Перед каждой операцией показывает план — можно одобрить, поправить, отменить.

Когда брать

  • Бардак в Downloads / на рабочем столе — разбор по категориям
  • Папка скриншотов чеков → табличка с суммами
  • Синхронизация двух папок между устройствами
  • Сборка отчётов из писем за период
  • Малый бизнес: payroll, bookkeeping (через Claude for Small Business)

Когда НЕ брать

  • Серьёзная аналитическая работа с ценой ошибки
  • Задачи, где нужен явный код и git-история
  • Сценарии, где требуется обширное многошаговое рассуждение

Типичные ошибки

  • Дать доступ ко всей файловой системе сразу — давай по папкам
  • Принять план не глядя — иногда Cowork предлагает странное
  • Использовать вместо Claude Code для разработки — это два разных продукта

Opus 4.7 и /fast

Карточка 4 · Opus 4.7 + /fast

Модельный апгрейд

Свежая модель Anthropic с заявленным контекстом 1M токенов. Команда /fast — ускоренная инференсная конфигурация того же Opus (не другая модель), ответ прилетает в 2–2.5 раза быстрее. Но дороже в 6 раз: $30/$150 за 1M input/output против $5/$25 у стандартного Opus 4.7.

Когда брать

  • Интерактивные задачи, где каждая секунда задержки реально мешает (живой дебаг, дизайн API)
  • Полный Opus 4.7 без /fast — для критичных задач, где важна точность и время не критично
  • Когда нужна максимальная глубина рассуждения — стандартный Opus, не /fast

Когда НЕ брать

  • Автономные задачи и долгие рефакторы — переплачиваешь ×6 за скорость, на которую не смотришь
  • Batch и CI/CD пайплайны — латентность не критична, стандарт дешевле
  • Не лезть выше 300–400K контекста — MRCR падает с 78% (Opus 4.6) до 32% (Opus 4.7)
  • Простые задачи без рассуждения — используй Haiku 4.5

Типичные ошибки

  • Включить /fast mid-conversation — pricing flat, и ×6 цена применяется ко ВСЕМУ предыдущему контексту задним числом, а не только к новым токенам
  • Не замечать косвенной деградации — на /fast токены сжигаются ×6 быстрее, rate-limit упирается раньше, сессия глохнет, не успев довести задачу. Формально качество то же, по факту — короче
  • Полагаться на 1M контекст без ручного /compact — пропустишь момент, модель уже не вытянет
  • Запускать долгие сессии без срабатывания /compact заранее — деградация накапливается
Памятка про /fast — пересмотрел позицию

Сначала /fast казалась прорывом. Бенчмарки одинаковые (SWE-bench Verified 87.6% и там, и там), модель та же — Anthropic честно говорят.

Но ×6 цена + flat pricing при переключении mid-conversation + быстрое исчерпание rate-limit'ов = по ощущениям дороже и хуже одновременно. Беру только когда реально сижу за компьютером и каждая секунда задержки бесит. Для автономных задач — стандартный Opus.

Памятка про контекст

0–200K Можно гонять как есть
200–400K Пора задумываться о /compact
400K+ Модель галлюцинирует, переключайся

MCP-серверы

Карточка 5 · MCP-серверы

Открытый стандарт

Model Context Protocol — открытый стандарт, расширяющий Claude Code внешними инструментами. К маю 2026 экосистема резко окрепла.

Минимальный набор для практика

  • context7 — свежая документация по любой библиотеке. Конец устаревшим ответам
  • playwright — запуск браузера, скриншоты страниц для UI-задач
  • shadcn — каталог компонентов с поиском и быстрой установкой
  • sequential-thinking — структурированное многошаговое рассуждение

Когда подключать в продакшен

  • Минимум неделя гоняешь на личных задачах
  • Проверил, что не крашит сессию на пограничных сценариях
  • Понимаешь, какие действия он может выполнить — у MCP-сервера могут быть widely разные права

Когда НЕ подключать

  • Community-проект без активности в репозитории больше 2–3 месяцев
  • Сервер просит избыточных прав без обоснования
  • Дублирует функциональность встроенного инструмента

Типичные ошибки

  • Подключить 10 серверов сразу — конфликт инструментов, Claude путается
  • Не настроить allowedPrompts — каждое действие требует подтверждения, замедляет работу
  • Доверять community-серверам без верификации источника

Комбо-приёмы, которые работают

Combo · 1Subagents + Skills

Один Explore-агент находит файлы → возвращает список. Skill write-pr-description принимает список → генерирует описание PR. Каждый занимается своим, контексты не пересекаются.

Combo · 2Skills + MCP

Skill migrate-from-supabase-v3-to-v4 внутри вызывает MCP context7 для свежей документации Supabase Auth v4 → не путается в устаревшем API.

Combo · 3Cowork + Claude for Small Business

Skill monthly-financial-report → Cowork тянет данные из QuickBooks и Stripe через connectors → собирает отчёт. Раньше — час бухгалтера. Сейчас — десять минут.

Combo · 4Opus 4.7 + /fast + ручной /compact

Длинная агентская сессия → каждые 150K токенов вручную вызываем /compact с понятными instructions → продолжаем работать без деградации. Не ждём, пока модель сама начнёт переспрашивать.

Что НЕ комбинировать

  • Hooks + длинные сессии в worktree — поведение хрупкое, hook может не сработать. Лучше явные команды в начале промта.
  • Memory system + короткие задачи — накладные расходы на ведение памяти не оправдывают пользу. Memory — для долгих проектов с регулярными возвратами.
  • Plan mode + simple задача — overhead больше пользы. Plan mode — для среднесложных задач с реальной декомпозицией.
  • 1M контекст + Opus 4.7 — даже Anthropic в system card рекомендуют 4.6 как fallback для long-context retrieval. Используй 4.7 только до ~300K.
