# Agent Teams в Claude Code: когда одного AI-агента недостаточно

Anthropic добавила возможность координировать команду из нескольких Claude, работающих вместе. Разбираюсь, когда это окупается, а когда — overhead.

## Контекст

Я управляю командой из 44 AI-агентов в проде. Основная проблема: **один агент упирается в контекстное окно**. Даже 200k токенов при анализе большого проекта заканчиваются быстро.

Anthropic решила это через **Agent Teams** — несколько экземпляров Claude с независимыми контекстами, которые общаются между собой.

## Чем это отличается от subagents?

| Параметр | Subagents | Agent Teams |
|----------|-----------|-------------|
| Коммуникация | Только с главным | Между собой напрямую |
| Координация | Главный управляет | Общий task list |
| Use case | Фокусные задачи | Коллаборация с дебатами |
| Стоимость | Ниже | Выше (каждый = отдельный Claude) |

## Когда это окупается?

**1. Параллельный code review**
- До: 1 ревьюер → находит 70% проблем
- После: 3 ревьюера (security, performance, tests) → находят 95%+

**2. Отладка с конкурирующими гипотезами**
- 5 агентов тестируют разные теории
- Спорят и опровергают друг друга
- Побеждает теория, которая выживает

**3. Разработка новых модулей**
- Каждый teammate владеет своей частью
- Параллелизация без конфликтов файлов

## Бизнес-метрики

**Стоимость:**
- 1 агент на task = 50k токенов (~$0.15)
- 5 агентов в команде = 250k+ токенов (~$0.75)

**Важно:** Если работаете через Claude.ai с подпиской **Claude Pro** ($20/мес), лимиты значительно выше. Для активного использования Agent Teams подписка окупается.

**ROI:**
- Code review находит на 25% больше проблем
- Отладка: от 4 часов до 1 часа (3x быстрее)
- Разработка модулей: параллелизация 3-5x

**Когда НЕ окупается:**
- Рутинные задачи (overhead > польза)
- Последовательная работа
- Редактирование одного файла

## Ограничения

Agent Teams — экспериментальная функция:
- Выключена по умолчанию
- Один тим на сессию
- Нет resume для in-process teammates
- Split panes требуют tmux/iTerm2

## Вердикт

**Для кого это:**
- Команды, где code review критичен (fintech, security)
- Проекты с комплексной отладкой
- Разработка с высокой параллелизацией

**Для кого это overkill:**
- Малые проекты
- Рутинные задачи
- Tight budget на токены
